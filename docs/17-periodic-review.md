# 17 運用開始後の定期レビュー

[← 目次へ戻る](README.md)

## 17.1 毎月または四半期

- 管理設定と実際の適用状態
- full access・bypass・例外利用
- 新規MCP・プラグイン・Hooks
- ネットワーク許可ドメイン
- 認証情報と権限
- 利用者・所属・案件
- 利用ログと異常操作
- シークレット検出
- エージェント・コンテナイメージ・主要依存の更新

## 17.2 製品更新時

- 新しい権限モード・ツール・外部連携が自動的に有効にならないか
- 既定の権限モード・自動承認の既定が変わっていないか（例: Claude Code は v2.1.228 で Pro/Max/Team の既定開始モードが auto mode に変わった。Codex の auto-review）
- 設定キーの有効スコープ（user / project / managed）が変わっていないか（例: `strictAllowlist` はプロジェクト設定では無効）
- 設定キーの廃止・既定値変更
- サンドボックスの対応OS・制約
- 管理設定が古いクライアントで無視されないか（例: Claude Code は `requiredMinimumVersion` で範囲外起動を拒否できる。Codex は全台の対応バージョンを別途確認）
- ネットワーク要件の変更
- experimental・beta 扱いの設定に依存している統制の仕様が変わっていないか（例: Codex の `[experimental_network]` と `features.network_proxy`。[10.5](10-codex.md)）
- データ取扱条件の変更

> [!NOTE]
> 製品更新時は[付録C 揮発値一覧](appendix-c-volatile-values.md)を再確認し、確認日を更新する。あわせて[15 受入テスト](15-acceptance-tests.md)を再実行し、更新前と同じ拒否結果が維持されることを確認する。

## 17.3 インシデント時

1. エージェント・トークン・MCPを停止
2. 到達可能だったシークレットを失効（エージェント自身のログイン情報・APIキー、MCPのOAuthトークン、Gitホスティング・パッケージレジストリのトークンを含む。[8.7](08-secrets.md)）
3. Git、クラウド、ネットワーク、エージェントのログとセッション記録（会話・ツール呼び出しの履歴）を保全
4. 変更ファイル、外部送信、外部操作を確認
5. 影響範囲を特定
6. シークレットをローテーション
7. エージェントのメモリ・プロジェクト指示ファイルに、注入された指示が残っていないか確認して除去（[2.7](02-terms-and-control-layers.md)）
8. ポリシー・設定・教育を是正
9. 顧客・法務・セキュリティへの報告要否を判断
