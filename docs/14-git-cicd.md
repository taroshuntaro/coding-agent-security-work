# 14 Git・CI/CD・本番操作

[← 目次へ戻る](README.md)

## 14.1 推奨フロー

```text
エージェント
  ↓
作業ブランチ内の変更
  ↓
開発者によるdiff確認
  ↓
テスト・静的解析・シークレットスキャン
  ↓
Pull Request
  ↓
人間のレビュー・承認
  ↓
CI/CD
  ↓
環境ごとの承認ゲート
  ↓
デプロイ
```

## 14.2 エージェントへ与えない権限

[00 R2](00-red-lines.md)の具体化である。

- 保護ブランチへの直接push
- PR承認
- 本番デプロイ承認
- 本番シークレット取得
- 本番DBマイグレーション適用
- IAM・RBACの変更
- 監査ログ削除
- セキュリティ設定の無効化

## 14.3 Git運用

- エージェント作業前に作業ツリーをクリーンにする
- タスクごとにbranchまたはworktreeを分ける
- 小さい変更単位にする
- 自動生成ファイルを含めてdiffを確認
- `.git`、Hooks、CI定義、IDE・エージェント設定の変更を重点確認
- force push、history rewriteを制限
- コミット・PRのAI利用表示方針を組織で決める

## 14.4 CI上でエージェントを動かす場合

CI（GitHub Actions等）でエージェントを動かすと、無人実行（[4.5](04-execution-architecture.md)）に加えて、**第三者が書いた入力でジョブを起動できる**という問題が生じる。Issue本文・PRの差分・コメントはそのままエージェントへの入力になり、ジョブが持つトークンやシークレットと同じ実行環境に置かれる（[3.2](03-risks.md)の3要素がそろいやすい）。

- **起動できる人を限定する**: リポジトリへの書き込み権限を持つ利用者の操作だけを起点にする。外部コントリビューターのIssue・コメント・フォークからのPRで、シークレット付きのエージェントジョブを自動起動しない。
- **信頼できないコードとシークレットを同じジョブに置かない**: GitHub Actionsの `pull_request_target` のようにシークレットや書き込みトークンを持つトリガーで、PR側のコードをチェックアウト・実行しない。
- **トークン権限を最小にする**: ワークフローで `permissions` を明示し、既定を読み取りにする。エージェントに必要な書き込み（作業ブランチへのpush・PR作成など）だけをジョブ単位で付与する。デプロイ用の資格情報を同じジョブに渡さない。
- **結果は作業ブランチとPRで返す**: 保護ブランチへの直接push、PRの自己承認、マージをさせない。ブランチ保護で人間のレビューを必須にする（[00 R4](00-red-lines.md)）。
- **アクションとエージェントのバージョンを固定する**: サードパーティのアクションはコミットSHAで固定し、エージェントのバージョンも固定して更新時に再テストする（[17.2](17-periodic-review.md)）。
- **ログの公開範囲を確認する**: エージェントの出力はCIログに残る。公開リポジトリではログも公開され得るため、マスキングと出力内容を確認する。
- **ランナーを使い捨てにする**: 永続的なセルフホストランナーは、前のジョブの状態や資格情報を次のジョブへ残し得る。エフェメラルなランナーを使う。
